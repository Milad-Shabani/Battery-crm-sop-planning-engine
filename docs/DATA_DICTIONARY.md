# Data Dictionary

All tables are generated by `crm_sop_planning.datagen` (seeded,
reproducible) and written to `data/raw/*.csv`. Dates: `2024-01-01` to
`2025-12-31` (2 full years, so two winter cold-snap cycles appear).

## Operations dimensions

| table | grain | key columns |
|---|---|---|
| `dim_employee` | 1 row per employee (~180) | `employee_id`, `role`, `department`, `production_line_id`, `shift`, `hire_date`, `monthly_wage_irr` |
| `dim_production_line` | 1 row per line (4) | `line_id`, `line_name`, `capacity_units_per_hour`, `shifts_per_day`, `changeover_minutes` |
| `dim_product` | 1 row per SKU (17) | `product_id`, `product_name`, `category`, `primary_line_id`, `capacity_ah`, `voltage`, `warranty_months`, `unit_price_irr`, `is_seasonal`, `seasonal_peak` |
| `dim_supplier` | 1 row per supplier (6) | `supplier_id`, `supplier_name`, `material_categories`, `avg_lead_time_days`, `reliability_score`, `payment_terms_days` |
| `dim_raw_material` | 1 row per material (12) | `material_id`, `material_name`, `unit_of_measure`, `unit_cost_irr`, `default_supplier_id`, `lead_time_days`, `safety_stock_days` |
| `dim_region` | 1 row per sales region (7) | `region_id`, `region_name`, `customer_type`, `payment_terms_days` |
| `bom` | 1 row per (product, material) | `product_id`, `material_id`, `qty_per_unit` — scales with `capacity_ah` |

## CRM dimensions

| table | grain | key columns |
|---|---|---|
| `dim_account` | 1 row per account (~70) | `account_id`, `account_name`, `account_type`, `region_id`, `annual_revenue_estimate_irr`, `credit_limit_irr`, `created_date` |
| `dim_contact` | 1-3 rows per account (~180) | `contact_id`, `account_id`, `full_name`, `title`, `email`, `phone` |

## CRM facts

| table | grain | key columns |
|---|---|---|
| `fact_leads` | 1 row per lead (~1,800) | `lead_id`, `created_date`, `source`, `owner`, `status` (Open/Qualified/Disqualified), `qualified_date`, `disqualify_reason` |
| `fact_opportunities` | 1 row per opportunity (~980) | `opportunity_id`, `account_id`, `lead_id` (nullable), `owner`, `product_id`, `estimated_quantity`, `created_date`, `estimated_close_date`, `stage`, `probability_pct`, `estimated_value_irr`, `status` (Open/Won/Lost), `actual_close_date`, `actual_value_irr`, `lose_reason` |
| `fact_cases` | 1 row per case (~450) | `case_id`, `account_id`, `contact_id`, `product_id`, `owner`, `priority`, `category`, `created_date`, `resolved_date`, `status` |
| `fact_activities` | 1 row per logged activity (~3-5K) | `activity_id`, `type` (Call/Email/Meeting/Task), `regarding_type` (Opportunity/Case), `regarding_id`, `owner`, `activity_date`, `duration_minutes` |

**Open vs. resolved opportunities** — the detail that makes the CRM useful
for forecasting: if `estimated_close_date` falls after the dataset's end
date, the opportunity is left `status="Open"` with a current `stage` and
`probability_pct`, no `actual_close_date`/`actual_value_irr`. Otherwise
it's resolved to `Won` or `Lost` (win rate varies by `account_type`) with
those fields populated. Only `Open` opportunities feed the forecast overlay
(`forecasting/pipeline_signal.py`).

## Operations facts

| table | grain | key columns |
|---|---|---|
| `fact_sales_orders` | 1 row per order (~800-900) | `order_id`, `order_source` (`Repeat` or `CRM Won`), `account_id`, `product_id`, `order_date`, `quantity`, `unit_price_irr`, `revenue_irr` |
| `fact_production_log` | 1 row per (date, line, product) produced | `date`, `line_id`, `product_id`, `planned_units`, `produced_units`, `scrap_units`, `downtime_minutes` |
| `fact_inventory_transactions` | 1 row per (date, material) event | `date`, `material_id`, `transaction_type` (`Consumption`/`Receipt`/`OnHandSnapshot`), `quantity` |
| `fact_purchase_orders` | 1 row per PO (~300) | `po_id`, `material_id`, `supplier_id`, `order_date`, `expected_delivery_date`, `actual_delivery_date`, `quantity`, `unit_cost_irr`, `status` |
| `fact_workforce_availability` | 1 row per (date, line, shift) | `date`, `line_id`, `shift`, `scheduled_headcount`, `present_headcount` |

`fact_sales_orders` blends two sources, tagged by `order_source`: most rows
are `Repeat` — recurring B2B reorders from existing accounts, generated
independently of the CRM — and a smaller slice is `CRM Won`, one row per
opportunity that resolved to `Won`, with `order_date` = `actual_close_date`.

## Pipeline outputs

Written to `data/processed/planning_warehouse.db` (SQLite), mirrored as
Parquet, **and** as sheets in `data/processed/SOP_CRM_Report.xlsx`:

| table / sheet | grain | key columns |
|---|---|---|
| `fact_demand_forecast` / *Demand Forecast* | 1 row per (product, forecast month) | `product_id`, `line_id`, `period_start`, `baseline_units`, `pipeline_units`, `forecast_units` |
| `fact_production_plan` / *Production Plan* | 1 row per (line, product, month) | `line_id`, `product_id`, `period_start`, `forecast_units`, `allocated_units`, `unmet_units` |
| `fact_material_requirements` / *Material Requirements* | 1 row per (material, month) | `period_start`, `material_id`, `required_quantity`, `projected_on_hand_start/end`, `below_safety_stock`, `recommended_order_qty` |
| `fact_sop_monthly_summary` / *Executive Summary* | 1 row per month | `period_start`, `forecast_units`, `allocated_units`, `unmet_units`, `fill_rate`, `revenue_captured_irr`, `revenue_lost_irr`, `materials_below_safety_stock` |
| `fact_forecast_accuracy` | 1 row per line + 1 overall | `line_id`, `mape`, `wape`, `n_months` |
| `fact_lead_funnel` / *CRM Pipeline & Funnel* | 1 row per lead source | `source`, `open`, `qualified`, `disqualified`, `total`, `conversion_rate` |
| `fact_win_rate_by_segment` / *CRM Pipeline & Funnel* | 1 row per account type | `account_type`, `opportunities`, `won`, `won_value_irr`, `win_rate` |
| `fact_rep_leaderboard` / *Sales Rep Leaderboard* | 1 row per sales rep | `employee_id`, `full_name`, `opportunities`, `won`, `won_value_irr`, `win_rate` |
| `fact_at_risk_accounts` / *At-Risk Accounts* | 1 row per account | `account_id`, `account_name`, `open_cases`, `days_since_last_order`, `at_risk` |
